# Connecting to a Backend

## How to connect the CLI to another engine daemon

A backend is a named engine daemon the CLI sends its commands to. `local`, the daemon on your own machine, is there from the start and selected. To add another you need its URL and the `ENGINE_SERVICE_TOKEN` it was started with. Keep the token in an environment variable rather than in commands: `export MAC_MINI_TOKEN=<the token>`.
Run `engine backend add` with a name for the daemon, its URL, and, with `--token-env`, the variable holding its token: `engine backend add mac-mini http://<its host>:4364 --token-env MAC_MINI_TOKEN`. (Both daemons in this guide run on `127.0.0.1`.)
![screenshot](./test2doc-5c33d56258ed.png)
Run `engine backends list --check` to see every backend, which one is selected (`*`), and whether each one is up.
![screenshot](./test2doc-570a14996db8.png)
Run `engine backend use mac-mini` to send every command after it to that daemon. `engine backends list` now marks `mac-mini` with `*`.
![screenshot](./test2doc-d226ea1129ad.png)
Commands now go to `mac-mini`. Run `engine graph add hello.yaml` to register a graph file from your project there.
To reach a different backend for one command only, add `--backend NAME` to it. `engine graphs list --backend local` lists the graphs on `local`, and leaves `mac-mini` selected.
`ENGINE_BACKEND=NAME` does the same for every command in a shell or script. `--backend` beats `ENGINE_BACKEND`, which beats the backend chosen with `engine backend use`.
